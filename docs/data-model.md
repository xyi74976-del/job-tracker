## 1. 字段清单

| 字段名（英文） | 中文名 | 类型 | 必填 | 举例 | 为什么需要它（没有它会怎样） |
|---|---|---|---|---|---|
| company | 公司 | string | 是 | 字节跳动 | 不知道投给谁，这条记录就没有意义 |
| position | 岗位 | string | 是 | 前端开发实习生 | 同一家公司可能投好几个岗（前端/全栈），只记公司会分不清 |
| city | 城市 | string | 否 | 杭州 | 找工作要按城市筛；但远程岗、没写城市的情况存在，所以不设必填，否则会卡住录入 |
| channel | 渠道 | string | 否 | BOSS直聘 / 内推 / 官网 | 投到第 30 家时你会想知道“哪个渠道回复率高”，没这个字段就永远算不出来 |
| salary | 薪资范围 | string | 否 | 150-200/天 | 面试谈薪要用；**存字符串不是数字**，因为“面议”“6k-8k”这种写不进数字 |
| appliedAt | 投递日期 | string | 是 | 2026-11-05 | 判断“投了多久没回音”；也是列表排序的依据。**存 `"YYYY-MM-DD"` 字符串**，可读可排序 |
| status | 状态 | string（枚举） | 是 | applied | 看板、统计、转化率全靠它。必须有默认值 `applied`，用户录一条就得有个初始状态 |
| notes | 备注 | string | 否 | 内推人张三，面试官问过闭包 | 面经、HR 说的话、“下次别再投这家”，都存这儿 |
| updatedAt | 最后更新时间 | string | 是，但**系统写入** | 2026-11-05T20:56 | 知道这条最近动过；以后做云端同步要靠它判断哪边新。**绝不能让用户手填**，手填必然错 |

## 2. 状态取值（枚举）

状态不能随便填，得有固定几个值，不然统计就没法做。

| 英文标识 | 显示中文 | 什么时候用它 |
|---|---|---|
| applied | 已投递 | 刚投出去，还没任何回音（新建记录的默认值） |
| viewed | 已查看 | 简历被打开 / HR 显示“已读” |
| written | 笔试 | 收到笔试、测评、作业邀请 |
| interviewing | 面试中 | 收到面试邀约，正在面（一面二面三面都算这个状态，轮次 v0.1 不细分） |
| hr | HR面 | 技术面过了，进入 HR / 谈薪环节 |
| offer | 已录用 | 拿到 offer |
| rejected | 已挂 | 简历被拒、面试挂、**或已读不回超过 30 天**（不这样定，统计会虚高） |
| withdrawn | 已放弃 | 你自己不去了（拿到别的 offer、看不上、嫌远） |

**口径比名字重要**：`rejected` 包含“已读不回超 30 天”这一条，是为了让“回复率”这个数字算出来是真的。以后你想加“已读不回”单独一个状态，就先算清楚统计要不要分开。

## 3. 现在不做、以后要加的字段

| 字段 | 为什么现在不加 |
|---|---|
| 面试时间 / 轮次 | 要支持“多轮 + 每轮独立时间”，是嵌套结构，v0.1 扛不住。等 v1.1 有日历视图时再加 |
| 简历版本 / 附件 | 要文件存储，v2.0 才碰 |
| 公司规模、行业、融资轮 | 想记的东西无限多，字段会膨胀成 Excel。先只记公司名，等真需要再拆 |
| 复盘原因（为什么挂） | 投够 20 家之后才有统计意义，现在加只会让你懒得填 |

## 4. 没想清楚的地方（附解答）

- **日期存字符串还是时间戳？** → 存字符串 `"2026-11-05"`。理由：人能读、能直接排序、能比较大小。时间戳要处理时区，v0.1 用不上。
- **薪资存字符串还是数字？** → 字符串。因为“面议”“150-200/天”“6k-8k”都不是数字。真要做薪资统计，v1.1 再拆成 `salaryMin` / `salaryMax` 两个数字字段。
- **状态要不要单独建一张表？** → v0.1 不用，用字符串常量就行。字段少的时候建表是过度设计。
- **要不要 `userId` 字段？** → v0.1 单用户不要。v1.0 接 Supabase 时加，那时才有“多用户”这回事。

## 与 PROJECT.md 的差异（对照结果）

- **我漏了**：`channel` 渠道、`salary` 薪资、`status` 状态、`updatedAt` 更新时间。
  → 教训：设计时先问“我投递这个动作发生了哪些信息”，比逐个想字段更不容易漏。
- **我多想了**：无。字段数量控制得不错。
- **我对了的地方**：`company` / `city` / `position` / `appliedAt` / `notes` 这五个方向全对；把类型写成 `string` 而不是“字符串”也对——它以后会原样变成 TS 的类型名。
- **命名修正**：`beizhu` → `notes`（拼音不能出现在代码里）；`date` → `appliedAt`（要说明是哪个日期）；`role` → `position`。
- **必填判断修正**：`city` 从必填改为**非必填**。原则是“**必填项越少，你越愿意录**”。只把“没有它记录就没意义”的字段设成必填——也就是 `company`、`position`、`appliedAt`。
